## 1. Purpose

This file is the **single, machine-checkable** form of the allowed-dependency
matrix described in
[`clean-architecture.md` §3](./clean-architecture.md#3-allowed-dependency-matrix).

The prose spec explains *why* the model exists. This file states *what the model
permits*, in a form that:

- a human reviewer can scan in under a minute, and
- the `internal/arch` package asserts against the real Go import graph on every
  `go test ./...`.

If this file and [`internal/arch/layers.go`](../../internal/arch/layers.go)
disagree, the golden test
[`TestLayerMatrixGolden`](../../internal/arch/layers_test.go) fails. If this
file and the real import graph disagree, `TestNoUpwardImports` fails. Either
failure blocks merge.

**Do not edit this file alone.** Any change here must be accompanied by a change
to `internal/arch/layers.go` and a regeneration of
`internal/arch/testdata/layer_diagram.golden.txt`, in the same PR, ideally under
a superseding ADR (see §7).

## 2. The matrix

Row = **importer**, Column = **imported**.
`✓` = allowed. `✗` = forbidden.

| importer ↓ \ imported → | Presentation | Application | Domain | Infrastructure | Shared |
|:------------------------|:------------:|:-----------:|:------:|:--------------:|:------:|
| **Presentation**        | ✓            | ✓           | ✓      | ✓              | ✓      |
| **Application**         | ✗            | ✓           | ✓      | ✗              | ✓      |
| **Domain**              | ✗            | ✗           | ✓      | ✗              | ✓      |
| **Infrastructure**      | ✗            | ✗           | ✓      | ✓              | ✓      |
| **Shared**              | ✗            | ✗           | ✗      | ✗              | ✓      |

**Total allowed ordered pairs:** 17.
**Total forbidden ordered pairs:** 8.
**Total pairs (including same-layer):** 25.

The diagonal is always `✓`: a layer may import itself (i.e. any package in a
layer may import any other package in the same layer). This is not an accident
of the table; it is a deliberate permission, because intra-layer coupling is a
matter for that layer's own design, not for the cross-layer guardrail.

## 3. The same matrix, transposed (imported-by view)

Reading the matrix by *column* answers the question "**who is allowed to import
me?**" — the view a security reviewer usually wants.

| Layer being imported | May be imported by                                          | Must NOT be imported by      |
|:---------------------|:------------------------------------------------------------|:-----------------------------|
| **Presentation**     | Presentation                                                | Application, Domain, Infrastructure, Shared |
| **Application**      | Presentation, Application                                   | Domain, Infrastructure, Shared |
| **Domain**           | Presentation, Application, Domain, Infrastructure           | Shared                       |
| **Infrastructure**   | Presentation, Infrastructure                                | Application, Domain, Shared  |
| **Shared**           | Presentation, Application, Domain, Infrastructure, Shared   | *(none)*                     |

Two observations:

- **Shared is the only universally importable layer.** This is by design: it
  holds primitives (`forgeerr`, logger interface, version) that every other
  layer legitimately needs.
- **Presentation is the only universally importing layer.** It is the
  composition root; if it could not see everything, wiring would be impossible.

---

## 4. Rules in prose

The matrix is a compact encoding of four rules. Every violation the tests can
catch traces back to one of them.

1. **The arrow points inward.**
   Inner layers never import outer layers. "Inner" means closer to the domain
   (Presentation → Application → Domain). Infrastructure is *outside* the
   domain in the dependency sense even though the diagram places it at the
   bottom: its dependency arrow points *inward* to Domain.

2. **Shared imports nothing above it.**
   Shared may import only Shared and the standard library. If a primitive needs
   upward knowledge, it belongs in that outer layer, not in Shared.

3. **The consumer defines the interface; the implementer implements it.**
   This is what makes the arrow point inward for Infrastructure. Application
   (or Domain) names the interface; Infrastructure provides the concrete type.
   Infrastructure *must not* declare interfaces "for" consumers.

4. **Presentation is the composition root.**
   It is the only layer that constructs concrete adapters and injects them into
   Application services. Every other layer receives its dependencies as
   interfaces via constructor arguments.

## 5. Import-path prefixes per layer

The `internal/arch` classifier maps a package's module-relative import path
suffix to a layer using **longest-prefix match**, with a `/` boundary. The
canonical rules live in `DefaultRules()`:

| Layer          | Prefix                        | First introduced | Notes                                            |
|:---------------|:------------------------------|:-----------------|:-------------------------------------------------|
| Presentation   | `internal/cli`                | Phase 1          | Composition root; owns exit boundary (ADR-019).  |
| Application    | `internal/application`        | Phase 2 (14.1.1) | One service per command.                         |
| Domain         | `internal/domain`             | Phase 2 (14.1.1) | Bounded contexts added in 14.2.x.                |
| Infrastructure | `internal/infrastructure`     | Phase 2 (14.1.1) | Adapters relocated here in 14.2.x.               |
| Shared         | `internal/shared`             | Phase 2 (14.1.1) | Primitives relocated here in 14.3.x.             |

**Prefix matching respects a `/` boundary.** `internal/applicationfoo` does
**not** match the `internal/application` rule and is therefore unclassified.
This is deliberate; it prevents accidental classification of packages that
merely share a name prefix. `TestClassify` in
[`internal/arch/layers_test.go`](../../internal/arch/layers_test.go) locks this
behavior in.

## 6. Grandfather allowlist

The following packages predate the layer model and are classified by **exact
match** against `DefaultGrandfathers()` in
[`internal/arch/layers.go`](../../internal/arch/layers.go). They are recorded
here so a reviewer does not have to open the Go source to see the debt.

| Package                          | Classified as   | Reason                                                | Removal phase |
|:---------------------------------|:----------------|:------------------------------------------------------|:--------------|
| `internal/app/version`           | Application     | Thin version service; folds into `internal/application`. | 14.2.x        |
| `internal/config`                | Infrastructure  | Config adapter; predates layer model.                 | 14.2.x        |
| `internal/filesystem`            | Infrastructure  | Filesystem primitives + policy (ADR-035).             | 14.2.x        |
| `internal/filesystem/safefs`     | Infrastructure  | Filesystem policy layer (ADR-035).                    | 14.2.x        |
| `internal/forgeerr`              | Shared          | Error taxonomy; predates layer model.                 | 14.3.x        |
| `internal/logger`                | Shared          | Interface + slog adapter co-located; split tracked.   | 14.3.x        |
| `internal/output`                | Infrastructure  | Renderer adapter; predates layer model.               | 14.2.x        |
| `internal/streams`               | Infrastructure  | Stream adapters; predates layer model.                | 14.2.x        |
| `internal/version`               | Shared          | Version metadata; predates layer model.               | 14.3.x        |

**Policy:** the allowlist must shrink, never grow, without a superseding ADR.
Every entry carries a `Reason` and a `RemovalPhase`; a missing phase fails
`TestGrandfathersHaveRemovalPhase`. The list is a **debt register**, not a
permanent classification.

## 7. Changing the matrix

Changing the matrix is an **ADR-level decision**, not a PR-level one. The
mechanical steps:

1. **Open an ADR** proposing the change, citing the requirement driving it and
   the alternative(s) considered.
2. **Edit `internal/arch/layers.go`:**
   - update `allowedImport` for the affected pairs,
   - update `DefaultRules` if a layer prefix changes,
   - update `DefaultGrandfathers` if the allowlist changes.
3. **Regenerate the golden file.** The canonical way is to run the test with an
   update flag (if the package provides one) or paste the output of
   `arch.MatrixGolden()` into
   `internal/arch/testdata/layer_diagram.golden.txt`. **Keep tabs as tabs**;
   editors that expand tabs will silently break the golden comparison.
4. **Edit this file and `clean-architecture.md` §3** to match.
5. **Run `scripts/arch/verify-layers.sh`.** `TestLayerMatrixGolden` will fail
   until the docs, the code, and the golden file agree. That failure is the
   point.

A PR that changes only one of the three representations (docs, code, golden)
will be rejected by CI.

## 8. Machine-checkable form

The canonical textual form of the matrix is the output of `arch.MatrixGolden()`.
It is stored in
[`internal/arch/testdata/layer_diagram.golden.txt`](../../internal/arch/testdata/layer_diagram.golden.txt)
and is byte-compared by `TestLayerMatrixGolden`.

Its format is:

- one header line: `importer \ imported` followed by tab-separated layer names,
- one line per layer: layer name, then tab-separated `allow` / `deny` cells.

Rendered for reference (tabs shown as `→`):

```text
importer \ imported→presentation→application→domain→infrastructure→shared
presentation→allow→allow→allow→allow→allow
application→deny→allow→allow→deny→allow
domain→deny→deny→allow→deny→allow
infrastructure→deny→deny→allow→allow→allow
shared→deny→deny→deny→deny→allow
```

If the golden file and this document disagree, **the golden file wins for the
test, this document wins for humans, and `layers.go` wins for both** — which is
why all three must be changed together.

## 9. Worked examples

### 9.1 Allowed: Application imports Domain

```text
internal/application/check   ──imports──▶   internal/domain/blueprint
```

Reason: Application orchestrates use cases by calling domain logic. This is the
normal direction of the arrow.

### 9.2 Allowed: Domain imports Shared

```text
internal/domain/blueprint   ──imports──▶   internal/shared/errors   (today: internal/forgeerr)
```

Reason: Domain needs the error taxonomy to classify failures. Shared is
universally importable.

### 9.3 Allowed: Infrastructure imports Domain

```text
internal/infrastructure/filesystem/osfs   ──imports──▶   internal/domain/foundation
```

Reason: Infrastructure implements interfaces declared by Domain (or by
Application). Importing the domain types it operates on is normal and expected.

### 9.4 Forbidden: Domain imports Infrastructure

```text
internal/domain/blueprint   ──imports──▶   internal/infrastructure/filesystem   ✗
```

Reason: inverts the arrow. The domain would couple to a concrete adapter. If
the domain needs to read files, it declares a narrow interface and lets the
composition root inject an adapter.

### 9.5 Forbidden: Application imports Infrastructure

```text
internal/application/check   ──imports──▶   internal/infrastructure/config   ✗
```

Reason: the use case wires its own adapter, breaking substitutability. The
composition root in `internal/cli` must do the wiring. If `CheckService` needs
config, it declares a `ConfigPort` and receives it.

### 9.6 Forbidden: Shared imports Domain

```text
internal/shared/errors   ──imports──▶   internal/domain/blueprint   ✗
```

Reason: turns Shared into a hub every package must import, and makes cycles
likely. If a primitive needs domain knowledge, it belongs in Domain, not in
Shared.

### 9.7 Forbidden: anything imports Presentation

```text
internal/application/check   ──imports──▶   internal/cli   ✗
```

Reason: Presentation is the outermost layer. Nothing below it may know about
Cobra, flags, exit codes, or rendering. This is what makes the CLI framework
swappable (ADR-002).

### 9.8 Unclassified (also a failure)

```text
internal/newthing   ──▶   (no rule, no grandfather entry)
```

Reason: closed-by-default policy. `TestEveryInternalPackageIsClassified` fails
until the package is placed under a layer prefix or added (with a Reason and
RemovalPhase) to `DefaultGrandfathers`.

## 10. Non-functional properties

| Property            | How this matrix supports it                                                                 |
|:--------------------|:--------------------------------------------------------------------------------------------|
| **Testability**     | Consumer-owned interfaces make Domain and Application fakeable without I/O.                 |
| **Substitutability**| Infrastructure implements interfaces declared elsewhere; swapping `osfs` for `memfs` is local. |
| **Reversibility**   | CLI framework (ADR-002), config format, and renderer are all confined to outer layers.      |
| **Auditability**    | The matrix is 25 cells; a security reviewer verifies the whole model in under a minute.     |
| **Determinism**     | `MatrixGolden` + `SortedGrandfathers` produce stable output for byte-comparison tests.      |
| **Fail-fast**       | Unclassified packages and upward imports fail `go test ./...`, not production.              |
| **Low coupling**    | Shared is the only universally importable layer; every other layer has a bounded fan-in.    |
