# Forge Supported Platform Matrix

**Matrix version:** `1.0.0`
**Applies to:** Forge `>= 1.0.0`
**Status:** Frozen (additive policy)
**Owner:** Release Engineering
**Reviewers:** Architecture

Forge is a single static binary. This matrix declares every platform on
which a Forge release is produced, tested, signed, and distributed.

## Summary

| Platform | GOOS/GOARCH | Tier | Min OS | CGO | Signing | Channels |
|---|---|---|---|---|---|---|
| Linux x86-64 | `linux/amd64` | 1 | glibc 2.28+ (or musl) | `CGO_ENABLED=0` | — | direct, apt, Docker |
| Linux arm64 | `linux/arm64` | 1 | glibc 2.28+ (or musl) | `CGO_ENABLED=0` | — | direct, apt, Docker |
| macOS x86-64 | `darwin/amd64` | 2 | macOS 12 (Monterey) | `CGO_ENABLED=0` | Notarization | direct, Homebrew |
| macOS arm64 | `darwin/arm64` | 1 | macOS 12 (Monterey) | `CGO_ENABLED=0` | Notarization | direct, Homebrew |
| Windows x86-64 | `windows/amd64` | 1 | Windows 10 21H2+ | `CGO_ENABLED=0` | Authenticode | direct, Scoop, winget |
| Windows arm64 | `windows/arm64` | 2 | Windows 11 | `CGO_ENABLED=0` | Authenticode | direct, winget |

## Tier Semantics

- **Tier 1** — Built, unit-tested, and **integration-tested in CI on every
  pull request and every release tag**.
- **Tier 2** — Built and unit-tested in CI on every release tag. Integration
  tests are run manually before a release and recorded in the release notes.
- **Tier 3** — Best-effort. Not built by the default release job. May be
  requested by users via `task release:tier3`. No SLA.

Tier 1/2/3 definitions are normative and live in
[`docs/reference/platform-tiers.md`](./platform-tiers.md).

## Static Linking

**All release builds MUST set `CGO_ENABLED=0`.** This is a hard requirement
of this matrix. Rationale:

1. Reproducible binaries across build hosts.
2. No runtime dependency on a C library version beyond the kernel ABI.
3. Cross-compilation from a single Linux builder for every target.
4. Container images can be `FROM scratch`.

A release that violates `CGO_ENABLED=0` fails the `platform:verify` task and
must not be published.

## Minimum OS Versions

| Platform | Minimum | Rationale |
|---|---|---|
| `linux/amd64`, `linux/arm64` | glibc 2.28 (CentOS 8 / RHEL 8 / Debian 10 / Ubuntu 20.04) | The oldest LTS kernel ABI Forge supports. Musl is accepted via the `-musl` variant. |
| `darwin/amd64`, `darwin/arm64` | macOS 12 (Monterey) | Oldest macOS still receiving Apple security updates at the freeze date. |
| `windows/amd64` | Windows 10 21H2 | Oldest Windows 10 build still serviced by Microsoft. |
| `windows/arm64` | Windows 11 | First Windows release with general-purpose arm64 support. |

## Code Signing

| Platform | Mechanism | Host requirements | Verification |
|---|---|---|---|
| `darwin/*` | Apple notarization + Developer ID code signature | Signing host needs Xcode CLI tools, a valid Developer ID Application certificate, and `notarytool` credentials | `spctl --assess --type execute` on a clean macOS 12 host |
| `windows/*` | Authenticode (EV or OV) | Signing host needs `signtool.exe`, a code-signing certificate in the Windows certificate store | `signtool verify /pa` on a clean Windows 10 21H2 host |
| `linux/*` | None (static binary). Release tarball signed with `cosign` keyless | None | `cosign verify-blob` |

macOS notarization requires network access to Apple's notary service on the
signing host. Windows Authenticode requires the certificate to be present in
the `CurrentUser\My` store. Both are documented in the release runbook.

## Distribution Channels

| Channel | Platforms | Notes |
|---|---|---|
| Direct download | all | Tarball (`.tar.gz`) on Linux/macOS, `.zip` on Windows, plus `cosign` signature and `SHA256SUMS` |
| Homebrew | `darwin/amd64`, `darwin/arm64` | Formula generated by `goreleaser` and pushed to `forge/homebrew-tap` |
| Scoop | `windows/amd64` | Manifest generated by `goreleaser` and pushed to `forge/scoop-bucket` |
| winget | `windows/amd64`, `windows/arm64` | Manifest generated by `goreleaser` and submitted to `microsoft/winget-pkgs` |
| apt | `linux/amd64`, `linux/arm64` | `.deb` via `nfpm`, published to `packages.forge.dev` |
| Docker | `linux/amd64`, `linux/arm64` | `ghcr.io/forge/forge:<version>` multi-arch manifest list, `FROM scratch` |

## Runtime Requirements

- **macOS**: The notarization host must have Xcode CLI tools installed
  (`xcode-select --install`). The `notarytool` binary is required. Users do
  not need Xcode.
- **Windows**: Authenticode requires the signing certificate to be importable
  into the `CurrentUser\My` store. Users do not need any SDK.
- **Linux**: No runtime dependencies beyond the kernel. The binary is static.

## Additive Policy

1. Adding a new platform is a **minor** change. It requires an entry in
   `platforms.yaml`, a row in this document, and a CI job.
2. Removing a platform is a **major** change. It requires a deprecation
   notice in the previous minor release and an entry in `CHANGELOG.md`.
3. Changing a tier (e.g. Tier 2 → Tier 1) is a **minor** change.
4. Changing a minimum OS version is a **minor** change if it is raised
   (narrowing support) and a **patch** change if it is lowered (widening).
5. This document and `platforms.yaml` MUST be updated in the same commit.
   The `platform:verify` task fails if they diverge.
